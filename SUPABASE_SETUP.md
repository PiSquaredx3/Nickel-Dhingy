# Supabase setup

The site is static and can stay on GitHub Pages. Supabase provides email/password accounts and stores the boards, topics, and replies.

1. Create a Supabase project.
2. In the Supabase SQL Editor, run [`supabase/schema.sql`](./supabase/schema.sql). It creates game and community boards with short descriptions of what belongs in each, including a Question of the Day board, account profiles, threaded replies, reply notifications, image buckets, post voting and medal awards, moderator pinning and featuring permissions, and row-level security policies. It does not add sample posts or members. Moderators post each day's question; replies close automatically 24 hours after the topic is created, and authors cannot edit or delete closed daily topics or replies. A moderator can feature one topic globally; it appears first in Recent Discussions and at the top of its board until unfeatured or replaced by another featured topic. The Forum News panel is stored in Supabase and can be edited on the site by global moderators. The baseline groups the forum into Community & Site, Games & Technology, Art & Media, and Daily Question sections, with rebalanced Any&All names and descriptions. When rerun on an existing project, it temporarily separates existing board positions to prevent unique-position collisions, updates the current board names and descriptions, moves topics and board-specific moderator assignments from retired legacy boards before deleting them, and preserves custom boards such as Rathner. This keeps existing topics and replies intact. Old links to legacy boards continue to redirect through the site's legacy-board mapping. The existing account with forum name `pi_` is granted global moderator status, and the existing account `iloveturdsandpopps` is assigned as a moderator only for the `rathner` board; make sure both accounts and the `rathner` board exist before running the script. Re-run the script on an existing project to apply updates.
3. In **Project Settings → API**, copy the Project URL and the **anon / publishable** key into [`supabase-config.js`](./supabase-config.js):

   ```js
   export const supabaseUrl = "https://YOUR_PROJECT.supabase.co";
   export const supabaseAnonKey = "YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY";
   ```

   Never put a `service_role` or secret key in this website.
4. In **Authentication → URL Configuration**, set the Site URL to the published site URL and add the published site URL (including its path, if applicable) to the allowed redirect URLs. For local testing, add `http://localhost:8000/**` as well. Password-reset emails return to the current page, where the user can choose a new password.
5. In **Authentication → Providers → Email**, choose whether new members must confirm their email. With confirmation enabled, sign-up sends a confirmation email before the member can log in.
6. Publish the site, then register an account and create a topic to verify the setup. Usernames containing admin/mod/staff/support/owner role names or reserved names identifying `pi_`/the site are rejected at signup and when a profile username is changed. The Members page lists public usernames in join-date order, numbered across pages (25 members per page). Board pages show each topic's average 0–1 rating and rating count, and let readers sort by recent activity or narrow the list to topics active in the last 24 hours or 7 days. Signed-in members can upvote or downvote each topic once; replies cannot be rated. A member's rating badge is based on the combined upvote share across all ratings on their authored topics. They need at least 10 total topic ratings to qualify: Bronze starts at 65%, Silver at 75%, and Gold at 90%. Only the highest qualifying badge is shown; downvotes count toward the average. Non-moderators are limited to 3 ratings per UTC calendar day; global moderators have no daily limit. Board moderators can moderate only their assigned board and do not receive global moderator privileges such as editing Forum News, featuring topics globally, or bypassing the rating limit. The schema starts a one-time 14-day voting grace period when first applied: all accounts can rate during the grace period, and accounts created during it remain eligible while they are younger than 14 days. Afterward, new accounts must be at least 14 days old. Re-running the schema does not restart the grace period. Votes cannot be edited or removed except by moderators deleting topics. Moderators can delete topics and replies.

The `rathner` board switches to a brown color palette while open and returns to the normal palette when navigating away.

Reply notifications appear beside the signed-in member's name and link to replies on topics they started or replies that directly target one of their replies. Notifications are individually marked read. Members can reply directly to a particular reply, and the parent reply is shown as context in the thread. Each topic and reply can include one optional JPG, GIF, WebP, or PNG image up to 2 MB. Run the updated SQL schema to create the notification table, reply threading and image fields, and access policies.

The public key is expected to be visible in a static website. Row-level security in the SQL schema restricts writes to signed-in members and ties each topic and reply to its author. Public visitors can read boards, topics, replies, and forum usernames. Email addresses are not exposed.
